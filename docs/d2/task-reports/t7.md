# Task report: t7, base commit recorded at accept time

Plan `d2-fleet-and-recovery`, task t7 (covers c52, h40).

## What I built

- `core/src/runs/base-commit.ts` (new): `resolveBaseCommit(repo, ref)` runs a read-only `git rev-parse --verify <ref>^{commit}`; a failure throws `invalid` with `field: repo` (a typed refusal). `startRef(options)` picks the ref the driver is configured with (`sandbox.ref` or `ref`), else `HEAD`.
- `core/src/runs/service.ts` (+3 lines, now 377): step 8 resolves the commit before the run is created, and stores it as `base_commit` on the record. This comes before the key file and the worker spawn, so a refused submit leaves nothing behind (no run directory, no key).
- Worker side: the driver reads `run.base_commit` from the stored record. `SandboxWorkspaceFactory` takes an optional `baseCommit` that replaces `settings.ref` in `prepare`; the claude-code and opencode drivers pass it. The stub driver uses `run.base_commit ?? options.ref`. `sandbox/worktree.ts` is unchanged on purpose: it already builds the bundle from the `ref` it is given, and that ref is now a full SHA.
- `contract/README.md`: the t7 rows are marked built.

## Choices

- The typed error is `invalid` with `field: repo`. The plan names no code, and the README only said "typed refusal".
- The ref resolved at accept time is the driver's configured ref (default `HEAD`), so a configured `CULTURE_AGENTS_RUN_REF` still means what it did.
- A run recorded before this change has no `base_commit`, and the drivers fall back to the configured ref.

## Acceptance criteria

1. Proven, in two parts.
   - `base-commit.test.ts` "the run record holds the HEAD of accept time...": the daemon records `base_commit` at submit and the host HEAD then moves; the stored record is unchanged.
   - "a stub run builds from the recorded commit although the host HEAD moved...": the worker's workspace is built from the recorded commit after HEAD moved.
   - "a sandbox run asks the bundle for the recorded commit...": the sandbox path passes the recorded commit to `prepare`.
   - Not run: the live sandbox and bundle with a real OpenShell. The bundle step is covered only by the existing `prepare` unit tests, which take whatever ref they are given.
   - The HEAD move is done in the test body, not by timing a real worker's start-up, so there is no race in the test.
2. Proven: "a repository with no commits..." (unborn HEAD) and "a repository whose HEAD cannot be resolved..." (a symbolic HEAD to a missing branch) both get `invalid` with `field: repo`.
