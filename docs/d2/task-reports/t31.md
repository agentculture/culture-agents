# Task report: t31, capability report reads the gateway's admit field

## Built

- `core/src/runs/gateway.ts` (new): `gatewayFromPayload` and `readGateway`. Asks `GET /status` at the origin of the OpenCode `baseUrl`, with Node fetch (injectable), 1 s default timeout (a race, so an injected fetch that ignores the abort signal still cannot delay a call). Reads `admission.admit`, `at` (RFC 3339), `stale_after_s`, `reason`. Unknown for: missing/ill-typed field, stale, future-stamped (more than 5 s ahead), bad JSON, timeout, refusal, non-2xx, a redirect that is not to loopback (loopback redirects are followed up to 3 hops). Concurrent reads share one request. No new dependency.
- `core/src/runs/admission.ts`: `readAdmission` is async and takes the gateway source and harness id; the gateway is consulted only for harnesses the source lists, otherwise `consulted: false`. `withHostReport` is async.
- `core/src/runs/ports.ts`: optional `gateway` on `HarnessCatalog`. `core/src/daemon/harness-catalog.ts` sets it for `opencode` from `config.opencode.baseUrl`.
- `core/src/runs/service.ts`: two lines changed in place (still 400 lines). Submit awaits the admission read; the capability documents use `Promise.all`.
- Docs: `contract/README.md` (gateway signal lines only), `docs/d2/part-one.md`, `CLAUDE.md` (one sentence), `docs/d2/part-one-acceptance.md` (live row).

## Choices and assumptions

- The gateway URL is `opencode.baseUrl` (default `http://host.openshell.internal:8001/v1`, the sandbox's view). `/status` is asked at its origin; that name may not resolve on the host, so the live read may need a loopback `baseUrl`. Not measured.
- No cache or background refresh: the read is async under a 1 s bound (service call sites were already async). A slow gateway can add up to 1 s to a submit or capability call.
- Existing test changed: `admission.test.ts` "the gateway is not consulted..." now awaits `readAdmission` and was renamed; its assertions are unchanged.
- Left unchanged: `contract/*.json`, fixtures, Python code.
